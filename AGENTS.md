# MGR OmniDev — coding agent rules

Read `HANDOFF.md` and `MGR-TRILOGY-HANDOFF.md` before any source mutation. Their **newest dated sections** supersede older historical entries.

- Respect the original 174 parent IDs and separate 28 MGR upgrades. Existing `open` does NOT prove absent implementation; source presence does NOT prove completed acceptance. Every promotion requires current passing test and immutable reference.
- Reuse `worker/fleet.mjs` / `worker/runner.mjs` as the only worker fleet. Never create a duplicate scheduler or bypass workerCapacity. Ten role lanes are not ten live, qualified AI agent processes.
- Keep Code Monster authoritative for census, candidate Git commits, campaign DAG and signed receipt policy; OmniSight is read-only projection; OmniDev authorizes jobs, model budgets and final promotion.
- DevMapGod is a product mode spanning the three repos; no new repository. No automatic code deletion from classifier guesses. Every proposed batch patch requires source hashes, tests and rollback strategy.
- Do not inherit credentials, send secrets into source or bypass owner release gates. Keep GitHub private repo boundaries. Review branch only until full tests/CI are green; no silent merge or deployment.
- Do not claim full certification from isolated fixture tests or a Docker simulator. Make Windows POSIX-only test fixtures portable or visibly skipped; keep Linux tests meaningful.
- Each build wave ends with exact commit/ref, tests and outputs, before→after, release blockers, updated `HANDOFF.md`, and a focused `UNFINISHED-WORK` ledger entry.
- Never delete old records to simplify dashboard totals, and never promise asynchronous work without a running worker service.
