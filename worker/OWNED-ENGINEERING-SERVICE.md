# Original engineering service in an owner runtime

`scripts/local-worker-api.mjs` exports `startLocalWorkerApi(configuration, {verifyPrivateState})`. The original laboratory CLI remains laboratory-only. An owner deployment requires trusted composition code and actual private-state verification; a JSON flag cannot supply that verification. ONE's `web/owner-omnidev-service.mjs` and fixed child `scripts/tevin-omnidev-service.mjs` implement the Windows owner composition.

The service uses original OmniDev SQLite jobs/records, routes, native assignments, accepted reports and recovery. Engineering metadata remains `engineering_verify` records in the same owning database. It is not another scheduler, shared business store or authority engine. ONE remains owner of conversation approval, settlement and saved result custody; API-MCP transports exact bounded operations.

## Startup and scope

The trusted parent verifies its owner directory, the saved host qualification against the current native launcher and Node executable, and the exact source/candidate/fixed-command digest scope. It protects its newly created fixed directories and verifies existing ones. Native policy, attempts, worker receipts, compiler snapshots and `omnidev.sqlite` stay under the exact protected `home/omnidev` root. ONE now derives scope through the original stored-source/candidate/oracle rules and supports exact stopped-owner policy replacement/recovery in original records. The service refuses startup with unresolved native_policy_change records; no hash-policy file must be written by the owner.

The parent sends three ephemeral distinct credentials and fixed configuration through its original child's stdin. Only nonce/PID/origin/source-fingerprint and bounded status frames return on stdout. Credentials stay in memory and are never model inputs or log output. The compiler reads only the original fixed 39-entry module map (38 unique emitted modules); owner snapshots use `__omniNodeLocalEnv`, test preparation retains `__omniEnv`. Source fingerprints bind compiler version, environment and all input bytes; existing snapshots are rehashed and reject extra or modified files rather than being overwritten. No request supplies executable modules or commands.

Owner storage is single-actor/single-tenant. A matching existing identity is required; another original service process cannot open the same owner's service root. Unknown or still-live lock ownership is refused. Only a confirmed absent prior process with a valid original marker permits stale-lock recovery. This is local host composition, not multiuser hosted acceptance or independent attestation.

## Bounded interfaces

Owner credential: original source import; account/native snapshot enqueue; submit the original account candidate; owner job decisions. Model inference, arbitrary review/automatic repair and general shell commands are not exposed by these local routes. Engineering credential plus exact configured actor/tenant: current binding, verification admission, status, accepted report and cancellation. The native worker has a distinct credential and cannot receive an internal verification override from an HTTP request.

`engineeringBinding(jobId, workspaceId)` checks current original project/job, native kind, candidate, immutable owner oracle, fixed native command, allowed digests and host identity. It rechecks project/job/policy after asynchronous hashing. The matching verification reservation alone may claim that job using the trusted internal composition argument. Public worker claims still refuse held or uncertain reservations. Existing signed Trilogy candidates remain explicitly outside this native contract.

URI identities decode once. Existing identifiers `.` and `..` cannot survive normal URL dot normalization, so the shared client uses exact-owner body reads at `POST /v1/engineering/verification-status` and `/verification-report`, with exactly `{requestId}`, and the original full binding at `/verification-cancel`. Normal encoded status/report/cancel paths remain compatible. Repeated reads do not create or retry execution.

## Stop, reopen and unknown results

Closing stops admission, requests cooperative cancellation of the original execution and waits for its settlement. The service refuses to claim release when native journal/quarantine or pending custody remains. ONE waits for the same child process and an explicit stopped frame with clear journal custody; a timeout retains the resource for observation/reconciliation. There is no force-kill/restart shortcut or unknown-result redispatch.

Normal restart reopens original SQLite records and native receipts. An assigned/running job without an accepted original result becomes unknown; completed replay reuses saved results. This does not prove crash-safe independent process-family custody under every host failure. Preserve failed fixtures, assignments, report journals and unknown records for their original reconciliation paths.
